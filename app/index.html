DevOps Flagship Platform

Project Goal

This project demonstrates a complete local DevOps and GitOps workflow using Kubernetes, Jenkins, ArgoCD, GitHub, and Datadog.

The goal is to simulate a production-style software delivery platform on a local machine while keeping the architecture lightweight enough to run on limited hardware.

How It Works

Application code and Kubernetes configuration are stored in GitHub. Jenkins runs inside a k3s Kubernetes cluster and uses temporary Kubernetes agent pods for CI jobs.

The Jenkins pipeline validates Kubernetes manifests, runs basic tests, builds a container image, pushes the image to a container registry, and updates the desired image version in Git.

ArgoCD watches the Git repository and automatically synchronizes the Kubernetes cluster with the desired state stored in Git. Jenkins does not deploy directly to Kubernetes.

Datadog monitors the Kubernetes cluster, application workloads, resource usage, and platform health.

Why This Architecture?

Jenkins is responsible for Continuous Integration: validation, testing, building, and publishing application artifacts.

ArgoCD is responsible for Continuous Delivery using GitOps. This separation keeps Git as the source of truth and prevents the CI system from directly modifying the production state.

Ephemeral Jenkins agents are used so build environments exist only while a pipeline is running, which reduces resource usage and avoids permanently running unnecessary build workers.
